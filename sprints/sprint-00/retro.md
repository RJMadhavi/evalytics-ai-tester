# Sprint 0 Retrospective

Held on: <date>. Look at how the work was done, not only what was done. Edit the suggestions below so they match what you actually felt.

## What went well

- The branch, pull request and automatic check routine caught problems before `main`, and it became a habit.
- Safety rules for automated tests were built before the first run against the real site.
- Observations were recorded as hypotheses with a status, not as confirmed defects.
- Problems were diagnosed step by step (the network block) instead of by guessing.

## What did not go well

- Too many items were in progress at once (up to four), and several waited on the owner.
- Some work happened without a story or issue on the board (the automation scaffold, the AI tools), so the board understates the effort.
- Commits straight to `main` were mixed with pull requests.
- A number was reported before it was checked (a test count), which cost a round of corrections.
- Dependencies on the owner were noticed late.

## What I will change in Sprint 1 (choose one or two)

| Change | How I will know it worked |
|--------|---------------------------|
| Work-in-progress limit of three items | The board never shows more than three In Progress |
| Create the issue before starting any work | No pull request without a linked issue |
| Send the owner a short update every week | Four updates by the end of Sprint 1 |
| Check every figure against CI or the board before reporting it | No corrections needed |
